Shipping a terminal UI means testing the terminal around your app, not only the widgets. Capabilities, fonts, widths, resize events, and cleanup all affect the release.

*By Max Wells, creator of [Rust/UI](https://rust-ui.com) and [Rustify](https://rustify.rs).*

> **TL;DR:** Ship reliable Rust TUIs by checking terminal capabilities, Unicode and width behavior, resize handling, cleanup on every exit path, and platform packaging.

## Check terminal capabilities

Detect color and Unicode assumptions through the selected backend and document a supported terminal matrix. Provide readable fallbacks when true color or special glyphs are unavailable.

## Handle resize and width

Recompute layouts from each frame area. Test double-width characters, combining marks, long paths, and narrow panes. Never use byte length as display width.

## Restore on every exit path

Leave raw mode and alternate-screen mode on success, `q`, errors, and panics where your terminal setup requires it. Add a small integration test for cleanup and a [TestBackend suite](/articles/test-ratatui-apps-testbackend) for visible behavior.

## Package and document

Build release binaries for the platforms you support, include install and upgrade instructions, and state backend requirements. Keep a changelog entry for behavior changes. The [event-loop guide](/articles/ratatui-keyboard-mouse-event-loop) covers reliable input and shutdown boundaries.
