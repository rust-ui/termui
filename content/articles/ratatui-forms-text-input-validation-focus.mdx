Terminal forms work when focus is obvious and validation is close to the field that needs attention. Widgets render controls; your app owns values, focus, and submit rules.

*By Max Wells, creator of [Rust/UI](https://rust-ui.com) and [Rustify](https://rustify.rs).*

> **TL;DR:** Let app state own form values, focus, and validation; make keyboard movement visible and predictable, then validate at submit or field boundaries with actionable errors.

## Define field state

Represent each field's value and validation separately from its visual widget. Keep a focus enum rather than scattering booleans across the screen.

```rust
enum Field { Name, Email, Submit }

struct FormState {
    focus: Field,
    name: String,
    email: String,
    error: Option<String>,
}
```

## Make keyboard flow predictable

Tab moves forward, Shift+Tab moves backward, and Enter submits or advances according to the field. Render a visible focus style and provide labels that remain understandable without color.

## Validate at the boundary

Validate on submit and when leaving a field if immediate feedback helps. Keep error text specific: say what value is expected and leave the user's input intact. After validation, return focus to the first invalid field.

## Compose existing controls

Start with [Text Input](/docs/widgets/text-input), [Text Area](/docs/widgets/text-area), [Checkbox](/docs/widgets/checkbox), and [Select List](/docs/widgets/select-list). Compose them in this article and test invalid, valid, and focused states.
